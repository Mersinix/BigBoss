## 3. Translation approach used

No new localization/i18n system was introduced. Strings were translated in place as plain French string literals, exactly matching the approach already used throughout the rest of the Supplier app (and consistent with the terminology established in prior localization tasks this session — e.g. "Chargement…", "Annuler", "Supprimer", the `aria-label="Close"` convention for custom dialog close buttons, and `aria-label="Ouvrir la recherche"` for mobile search toggles). The one structural addition is the new `STATUS_LABELS: Record<PromotionStatus, string>` constant (§2) — a minimal, file-local display map following the exact same pattern as the pre-existing `TYPE_LABELS` and `STATUS_STYLES` maps already in this file, not a new mechanism.

**One deliberate exception, flagged explicitly**: the hardcoded fallback default `'Free gift'` (used when a supplier creates a GIFT-type promotion but leaves the "Gift Description" field empty) was translated to `'Cadeau gratuit'`. This value gets persisted into the `giftInfo.description` database field and is later displayed verbatim to customers in the Cafe cart page (`client/src/pages/cafe/cart-page.tsx:1051`). Since this is a static interface default (not supplier-entered content) that becomes customer-facing text, it falls under "translate the interface" rather than "preserve user-generated content." As with prior stored-then-displayed defaults translated earlier this session, this only affects **newly created** promotions going forward — any already-existing promotion in the database that relied on this fallback keeps its stored English `"Free gift"` value, since no database row was modified.
