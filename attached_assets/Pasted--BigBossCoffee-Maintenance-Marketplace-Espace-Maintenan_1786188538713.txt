# BigBossCoffee — Maintenance Marketplace ↔ Espace Maintenance Full Synchronization

We now need to complete the synchronization between the **Coffee Owner Maintenance marketplace (`/maintenance`)** and the **Maintenance account / Espace Maintenance**.

The goal is to transform the current Maintenance marketplace from partially static/demo data into a **fully real, database-backed, synchronized marketplace**, connected to the real Maintenance accounts, reservations, messages, favorites, availability, profiles, and realtime updates.

## ⚠️ CRITICAL RULES — READ BEFORE MAKING ANY CHANGE

Before changing any code, **first analyze the existing implementation and architecture of both sides**:

* Coffee Owner → `/maintenance`
* Maintenance account → `Espace Maintenance`
* Existing authentication and roles
* Existing database schema
* Existing Maintenance APIs
* Existing messages system
* Existing favorites system
* Existing reservation/booking system
* Existing realtime synchronization mechanisms
* Existing dark/light theme system
* Existing service visibility/system management
* Existing profile/account structures

Do NOT start implementing immediately.

First understand how the existing application already works and identify the existing patterns that should be reused.

### VERY IMPORTANT

* Do NOT redesign the application.
* Do NOT change the existing design unless explicitly requested below.
* Do NOT remove existing components or functionality.
* Do NOT modify unrelated modules.
* Do NOT change existing behavior that is already working.
* Do NOT replace existing architecture unnecessarily.
* Reuse existing database models, APIs, stores, hooks, realtime mechanisms, authentication, messaging, favorites, reservations, and UI patterns whenever they already exist.
* If something already exists and works, extend it instead of creating a parallel implementation.
* Do not introduce duplicate systems.
* Do not create a second messaging system, favorite system, reservation system, profile system, etc.
* Do not change the existing SHOP functionality.
* Do not change PRINT, BARISTA, MARKETING, or other marketplace functionality.
* Do not change the Maintenance design except for the specific visual synchronization requested below.
* Preserve responsive behavior.
* Preserve translations.
* Preserve existing navigation.
* Preserve existing permissions and authorization.
* Preserve existing System Management service visibility behavior.
