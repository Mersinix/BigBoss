Objective

Currently, the entire project displays prices using a fixed currency symbol (for example: $).

We now want a single global currency configuration controlled by the Admin.

The selected currency should automatically be used everywhere in the application.

The currency is only a display setting.

Do not convert prices.

Do not recalculate values.

Only change the currency symbol shown throughout the application.

2. Global Project Currency

When the Admin selects a currency:

The selection becomes the global project currency.

Every price displayed anywhere in the application must immediately use this selected currency.

The change must be applied consistently throughout the project.

4. Existing Prices

Do not modify stored prices.

Example:

If a product price is stored as:

20

and the Admin selects:

$

Display:

$20

If the Admin later selects:

DT

Display:

DT20

No price conversion should occur.

Only the displayed currency symbol changes.

5. Realtime Synchronization

When the Admin changes the currency:

The update should propagate throughout the application.

Every user should see the new currency consistently.

No manual refresh should be required where realtime synchronization already exists.

Keep the existing synchronization behavior intact.

6. Persistence

The selected currency must be saved as a global system setting.

If the server restarts or users reconnect:

The last selected currency should still be used throughout the project.

7. Future Compatibility

Implement the currency management so that future modules automatically use the same global currency without requiring additional changes.

Avoid hardcoded currency symbols throughout the project.

All price displays should reference the single global currency configuration.
