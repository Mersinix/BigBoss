You are a senior full-stack engineer specializing in Google Maps Platform, Express.js, TypeScript, React, PostgreSQL, and scalable lead-generation systems.

# Project Context

We have an existing Google Places prospecting feature inside our admin dashboard.

The current flow allows an admin to search for coffee shops and create prospects.

Current frontend fields:

* Search Center Address

  * Example: Tunis, Nabeul, Avenue Habib Bourguiba...
* Radius
* Min Rating
* Search Keyword

  * Default: coffee
* Prospect Type

  * Auto Detect
* Only businesses with phone
* Only businesses with website
* Cancel
* Search

Current backend endpoint:

```
POST /api/admin/prospecting/search
```

The current implementation:

1. Receives an address.
2. Uses Google Geocoding API.
3. Executes Google Places Nearby Search once.
4. Uses pagination.
5. Saves returned places as prospects.

The problem:

Google Nearby Search only returns approximately 60 places maximum per search center.

For cities like Tunis, Nabeul, Hammamet, Sousse, etc., this is not enough.

We need a production-grade local business discovery system capable of finding significantly more coffee shops in a selected geographic area.

---

# Main Objective

Replace the current search engine implementation with a geographic grid-based Google Places discovery system.

Do NOT create a new endpoint.

Keep:


and improve the internal implementation.

Do not break existing frontend functionality.
