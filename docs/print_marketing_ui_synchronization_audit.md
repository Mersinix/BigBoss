# Print / Marketing / Academy / Barista — Synchronization & Shared UI Audit

Scope per task: Coffee Owner `/print`, `/marketing`, `/academy`, `/barista`, Admin `/admin/print > Catégories`,
and the shared Coffee Owner modal components these four verticals use.

| 9 | Review data synchronization, no duplicate storage | **ALREADY CORRECT, confirmed** | Single shared table `supplierProductReviews` (`shared/schema.ts:1433+`) with a `reviewType` discriminator (`'PRINT'`/`'MARKETING'`/`'ACADEMY'`/etc., `storage.ts` hardcodes the literal on insert and filters on read). No per-printer/per-marketing denormalized rating column — `rating`/`reviewCount` are computed live from this table on every marketplace-card read, so React Query cache invalidation after a review mutation is the only sync mechanism needed, and it already exists per-vertical (`useCreatePrintReview`, `useCreateMarketingReview` already invalidate the relevant marketplace/company/reviews query keys). Moving the UI into a modal does not change any of this — pure presentation move. |
| 10/11 | Provider details modal content / categories preserved, no hardcoding | **ALREADY CORRECT, not touched** | `printerProfiles` has no categories column; category "ownership" for a provider lives on `users.printCategories`/`printSubCategories` (`text[]`, plain names, validated-by-name against the taxonomy on write — `storage.setPrinterCategoryMapping`). `printCatalogItems.category`/`subCategory` are also plain text, deliberately not FK'd (explicit schema comment: "a deleted/renamed taxonomy entry never corrupts historical catalog/order data"). This means category/subcategory identity in this app is **soft-linked by exact name match**, not by numeric id — the icon-sync fix (item 1) must therefore match on `taxonomy.name === catalogItem.category` (already the established convention elsewhere), not invent an id-based relationship that doesn't exist in the schema. |
| 12/13 | Favorite icon visual consistency + dark mode, Print as reference | **NOT DONE** | Print's card-level favorite button (`print-page.tsx:180-201`) wraps the heart in `` `...${isDark ? "bg-gray-800/90" : "bg-white/90"}` `` — a dark-mode-aware circle background. Academy (`barista-academy-page.tsx:246-266`), Marketing (`marketing-page.tsx:213-225`) and Barista (`barista-page.tsx:252-295`, `BaristaCard`) all hard-code `bg-white/90` with **no** `isDark` branch at all — in dark mode this renders a glaring white circle, exactly the "incorrect contrast" the task describes. The heart icon's own classes (`text-gray-400` default / `fill-rose-500 text-rose-500` favorited) are already identical across all four — only the circle background needs the same `isDark` branch Print (and, per the Barista audit, Maintenance's `AgentCard`) already has. Modal-level favorite buttons (on the hero image, `bg-black/40`) are already theme-agnostic by design and need no change. |
| 14/15/16/17 | Signaler modal matches Disponibilité's visual design, content/functionality preserved, close button on the right everywhere | **NOT DONE** | 9 Signaler dialogs exist (Maintenance, Barista, Academy×2, Delivery, Print×2, Marketing×2), every one a bare `VisuallyHidden DialogTitle` + plain red text line + `Textarea` + Annuler/Envoyer row, using the **default** shadcn `DialogContent` close button (`client/src/components/ui/dialog.tsx:51-56`, `absolute right-4 top-4`, small low-contrast X) — already on the right, but visually inconsistent with Disponibilité's distinct circular button. Meanwhile the ~7 "Disponibilité" modals (Maintenance/Barista/Academy×2/Print-company/Marketing — `[&>button]:hidden` + a hand-built `w-8 h-8 rounded-full` X button) put that nicer button on the **LEFT** (first child of a `justify-between` header, balanced by a trailing spacer div) — i.e. Disponibilité is simultaneously the *design* reference the task wants copied AND itself the modal most clearly violating "must be on the right." Fix: (a) swap the button/spacer order in every Disponibilité modal's header so the same button lands on the right; (b) give every Signaler dialog the same circular-button chrome (hide the default via `[&>button]:hidden`, add the Disponibilité-style button, keep it top-right), with zero change to Signaler's textarea/report content/mutation. |
| — | Nested modal state preservation (scroll/selection/search/review state) | **Addressed by item 3/4's fix directly** | Since the fix makes both modals independently stateful `<Dialog>`s that are never forced closed, React never unmounts the parent `PrintServiceDetailModal`/`MarketingServiceDetailModal` while the child is open — its internal state (scroll position, selected item, review draft) is preserved automatically, with no extra state-preservation code needed. |
